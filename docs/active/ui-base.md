# UI 基础层契约（ui-base）

> 这是什么：2026-08-30 用户拍板立项的 na UI 架构契约——硬切换基座 +
> 基础层内置采样缝 + 动画全插件。四节契约 + 纪律条款表 + 决策记录。
> 性质：契约文档（纪律载体，随实现增补；本文档自举三行块排版纪律）。
> 关联：`立项.md`（三层架构）/ `multi-end-layering.md`（分层宪法——
> ui-base 全部落在壳层，核心层零触碰）/ kfmv4 `term-contract.md`（先例）。
> 状态：已立项未实现。第一消费者=AI 对话面板（先 AI 后文件树），
> 控件与缝从它身上提取，提取一个登记一个。
> 视觉基调（2026-09-04 用户拍板）：像素+霓虹+精灵球的游戏感是底色，
> 体验层不复刻 kfmv4（协议层兼容照旧），游戏感住长什么样、不住动不动。

## 一、总架构

- 基础层**只写目标值**：状态变化瞬时生效，渲染下一帧即达（硬切换）。
- 基础层内置**采样缝**：可动画属性渲染时过一道槽位，无插件占槽则直通
  目标值——`rendered = anim_slot(prop).sample(now).unwrap_or(target)`。
- 动画全是插件（ui-fx）：占槽驱动插值，拔掉后功能等价，只是变糙。
- 主题包 = 调色板 + 字体 + 曲线绑定，填的正是同一批槽。

## 三、槽位 API（缝）

- 槽位占用作为 cordis-na 插件面的一类 capability，manifest 声明占用哪些槽。
- 组合策略 v1：每属性单槽，后占者赢，不做混合栈（等真实需求逼出来再议）。
- 铁律：**缝不能后补**——没有缝，任何动画都要改每个控件。动画可后插，
  缝不行，所以缝随第一消费者首次动工一次落位。

## 四、帧时钟策略

- 按需启停：无活跃动画 = 零额外帧、零唤醒申请（对照夜判据：na 自身
  0.45% 单核不许被动画系统抬升）。
- 帧预算 = 显示真实刷新周期（BAR-077，2026-09-10 拍板）：壳每次
  resumed 经 JNI 读 `Display.getMode().getRefreshRate()` 喂核心层，
  120Hz 屏 8ms / 60Hz 屏 16ms 自适应；未喂前默认 16ms 保守基线，
  钳 4~33ms 防病态。旧契「上限 60fps」废止——120Hz 屏硬钳 60fps
  = 屏幕每刷两次画面才动一次 = 肉眼拖影。最后一个动画结束即停表。

## 五、基础层-插件分界表

| 项 | 归属 | 判据 |
|---|---|---|
| 目标值语义（内容不被键盘盖、行带位置） | 基础层 | 语义，拔不得 |
| fling 惯性滚动 | 基础层 | 决定「看哪一行」=语义 |
| 键盘避让的目标值计算 | 基础层 | 同上 |
| 键盘避让的呈现动画 | ui-fx 可占 | ~~只许镜像键盘自身轨迹（逐帧 insets），禁自造补间~~ **2026-09-04 用户拍板改判**：100ms 轮询（BAR-006 事件驱动死路）拿到的轨迹是阶梯，纯镜像实看太硬——改为轮询采样点间弹簧平滑；目标值仍恒等于真实 inset（缝只许插值），终端 resize 不过缝 |
| 面板/卡片/浮层进出场动画 | ui-fx | 拔掉=功能等价只是变糙 |
| 快捷键行 | 层级低于 AI 面板 | 过渡帧照画：被落下的面板盖住是自然结果；硬切拿走 = 两端 pop 闪烁（BAR-063） |
| 主题（调色板/字体/曲线） | 主题插件 | 填同一批槽 |
| 终端格子内容 | 永不动画 | 可读性+性能红线 |

| 动画不碰终端格子 | 动画运行中 grid 快照逐字节不变 |

## 七、渲染成本模型（图层烘焙，2026-09-07 随 AI 面板动画立项落地）

> 用户拍板「干脆先把引擎做好，未来做 UI 减少重复劳动」——本节是
> ui-base 缺的另一半：§一~四管「值怎么变」，本节管「变的成本谁付」。

- **槽位**：每块静态可烘焙面 = 一个槽（ChromeSlot：画布+纹理+可见性）。
  首批三槽：键行 / AI 面板底 / 上层 chrome（输入栏+光球+放大镜）。
  菜单/工具卡/对话框等未来 UI 入册即白拿「动画零光栅」。
- **烘焙**：内容 sig（LayerSigs）变化 → 重光栅槽画布 + 一次上传
  （slot_bake）。sig 必须列全 paint 读过的每个输入，漏输入=鬼影。
- **动画**：placement/alpha 变换在合成期进实例 rect（layer_prog），
  **永不触碰槽画布**——AI 面板 panel_off 即第一实例（烘焙画布恒为
  靠泊位，panel_off 不进 sig）。
- **每帧内容**（终端网格、AI 文字实例）走 GPU 实例管线，与槽位正交。
- **已知的期 2 债**（记入 state.md 欠账）：①键盘避让期 ime 逐帧变 →
  面板环/键行带 sig 含 ime 仍逐帧重烘焙（面板环改「inset=0 烘焙 +
  placement 平移」需解决顶缘不等价问题）；②槽画布 v1=全屏尺寸，
  条带槽（键行/输入栏）改条带画布省内存省上传；③放大镜内容跟网格活，
  拖选期强制重烘焙（正确性换性能，可接受）。
- 判卷仪表：panel-anim（动画期逐帧）/ gles-stage（300 帧滚动）照旧。

## 八、决策记录（三行块自举——拍板理由入库）

【D1】总架构
决定：硬切基座+基础层内置采样缝+动画全插件+主题填槽
理由：动画可后插，缝不可后补（改缝=改每个控件）；硬切基座=确定性系统，考题只断言终态
否决案：一体式动画（拆不出去/主题无槽可填）；缝也插件化（插件没有可挂的钉子）
标签：成本不对称

【D2】交互语义归属
决定：fling 与避让目标值在基础层；避让呈现动画可占槽但只许镜像键盘自身轨迹
理由：fling 决定「看哪一行」是语义；跟踪参考轨迹不添延迟，自造补间添延迟且失同步时输入区被盖
否决案：键盘避让一律禁动画——把「跟踪」与「自造补间」混为一谈（2026-08-30 用户否决后改立本条）
标签：能观能控

【D3】控件来源
决定：控件库锚定第一消费者提取式生长；收编进库需 ≥1 真实消费者+1 考题
理由：无消费者的通用控件库是想象设计；需求不会自己长，但会长在真实消费者身上
否决案：先造通用控件库再找消费者（2026-08-30 用户质疑「需求不会自己长」后合议定案）
标签：打脸结晶

【D4】排版纪律
决定：含决定的条目尾部带 决定/理由/否决案 三行块；理由挂四标签封闭集（打脸结晶/外部判据/成本不对称/能观能控）
理由：拍板理由入库=二阶控制的第一个传感器（需求冶炼笔记 §三）；否决案栏让未来 agent 不翻案
否决案：自由文本无格式（需求冶炼笔记开放问题一的悬置态——理由不可机械检索）
标签：外部判据

【D5】键盘避让动画改判（2026-09-04 用户拍板，修订 D2）
决定：chrome（输入栏/快捷键行）跟键盘开合走弹簧平滑——开第二道缝「键盘 inset」；终端 resize 不过缝，永远吃真实值
理由：事件驱动在本机是死路（BAR-006），100ms 轮询拿到的轨迹是阶梯，纯镜像实看太硬（用户原话「没有对应动画，显得很硬」）；D2 的「禁自造补间」防的是失同步盖输入区，弹簧恒向真实 inset 收敛不失同步
否决案：纯镜像轮询阶梯（=现状，用户判硬）；终端网格也跟动画 resize（pty 抖动红线）
标签：打脸结晶

【D6】渲染成本模型=图层烘焙引擎（2026-09-07 用户拍板「干脆先把引擎做好」）
决定：槽位烘焙（sig 置脏）+ placement/alpha 合成期变换；动画帧永不触碰槽画布；首批三槽随 AI 面板动画落地，未来 UI 入册即白拿
理由：面板动画实测 68fps+28~37ms 毛刺的病根=动画期全画布重光栅+全屏上传；逐 UI 打补丁是重复劳动，引擎化一次投入（浏览器/Flutter/游戏精灵同款分层合成，外部判据）；不引外部引擎（wgpu 判死先例），槽位设施 ~200 行落在壳层
否决案：逐 UI 单独优化（每块新 UI 重复交一遍学费）；直接上成熟 UI 引擎（体积/控制权代价，且缝+槽架构已自洽）
标签：成本不对称
