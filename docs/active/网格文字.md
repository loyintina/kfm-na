# 网格文字引擎（BAR-178，2026-09-29 立）——布局唯一源

> 终端页之外的 UI 文字，从此与终端同一把尺：**全角 2 格、半角 1 格、
> 控制符 0 格**，格 = `TermView.cell_w/cell_h`（基准 `CELL_W=18`/
> `CELL_H=36`，pinch 双指缩放改实例字段，`set_cell_size`）。
> 本档是引擎的唯一契约；消费面迁移进度见追踪信 0017。

## 一、定位

旧世界：14 个 UI 面各写「硬编码 px + fontdue 自然步进」（文件树
`FT_TEXT_PX=44`、配置页、标签栏……），与终端的字符网格两套尺——
theme.md §一 内容层条款（「字号走格子变量，双指缩放全部 UI 自动同源
缩放」，A5 拍板）的欠账。本引擎是还账的**唯一合法路径**：任何 UI
文字的宽度分类、折行、落笔都走这里，不许再就地造尺。

## 二、三件形制

1. **格宽分类** `ui::grid_text::char_cells` / `grid_text_cells`
   （`src/ui/grid_text.rs`，纯函数）：判据 = unicode-width（alacritty
   终端网格同一个 crate——终端画几格，UI 就量几格）。这是终端全角
   两格口径的 UI 侧**唯一源**，收编 `tab_bar::text_cells` /
   `modal::wrap_text` 的 0x2E80 土判据（盲区实例：全角标点
   U+3000–U+303F 在 0x2E80 之前，土判据误判 1 格）——两处本单未动，
   挂账见 §五。
2. **格折行** `ui::grid_text::grid_wrap`：贪心按格断行（累计格数超
   `max_cells` 即断；断点优先行内最后一个 ASCII 空格之后，空格留
   上行尾；没有就硬断——`ft_wrap_split` 同款贪心语义；行首第一字
   恒收，病态窄行不死循环；零宽字符不占格）。返回 char 下标区间。
3. **格落笔**（`TermView` 侧胶水，`src/termview.rs` 尾部
   「══ 网格文字引擎（BAR-178 布局唯一源）══」impl 块——
   cell/font 私有字段只有该模块够得着）：
   - `grid_fit()` → (主 px, 主 baseline, cjk px, cjk baseline)：
     用实例格现值调 `fit_font_px`/`fit_cjk_px`（fit_* 既有语义不动，
     termview_spec 钉零惊动）；
   - `measure_items_grid(text)` → (items, 总格数)：逐字 `pick_font`
     （缺字记 tofu 跳过），步进 = `char_cells × cell_w`；
   - `draw_grid_text_left(frame, items, x0, y_top, cell_w, max_px_w,
     fg, clip_y)`：pen 从 x0 起按格步进，**字形在自身格跨内水平居中**
     （全角字 2 格内居中；墨不许溢过本字格跨右缘，终端 `clip_w`
     同律），baseline = y_top + 对应 baseline_off，恰好满宽 = 装得下
     （BAR-088 同律），光栅走 `rasterize_cached`。

## 三、字号两来源条款

- **运行期字号 = `grid_fit` 读 TermView 实例格**——pinch 改格后所有
  走引擎的 UI 文字自动同源缩放（A5 条款落地）；
- **基准常量 `CELL_W/CELL_H`（18×36）不动**——它仍是 pinch 的 1.0
  锚点与冷启动默认；
- 派生 px 常量表（如 `filetree::ROW_H=90`）是**基准格下的 px 身**：
  基准不变时与格账一致；实例格被 pinch 改后 px 表不自动跟（挂账
  §五②）。
