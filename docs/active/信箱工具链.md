# 信箱工具链（mailbox-core / mailbox-cli）

> 2026-09-29 立。kfmv4 信箱 JS 三件套（`kfmv4/scripts/check/new-letter.mjs` /
> `check-letter-token.mjs` / `gen-agent-inbox.mjs`）的 Rust 忠实移植，
> 派活 = na 信箱 0004 号提案。分层：逻辑全在 `crates/mailbox-core`
> （纯函数零 IO——不碰文件系统、不取时间，A 档判卷）；IO 全在
> `crates/mailbox-cli`（读目录/写文件/`date` 取时//dev/urandom 发 nonce）。
> 规约唯一出处仍是 kfmv4 侧 `docs/ledger/mailbox-contract-v2.1.md`（只读引用）。

## 五子命令

```bash
cargo build -p mailbox-cli   # 产物 target/debug/mailbox-cli

# new —— 写信 + 发令牌（v2.1 模式；骨架/文件名/fp/台账行与 JS 逐字节一致）
mailbox-cli new --from-func 研究部 --from-name 清和 \
    --to 评审部白露 [--to 开发部观澜] [--to-all] \
    [--reply 0004] [--about 测试事由] \
    --type 通报 --title "标题" [--kind 征集] [--expect …] [--criteria …] [--status 待回信]
# 注入口（golden/复现用）：--now-local "YYYY-MM-DD HH:MM ±HH:MM" --now-utc <ISO> --nonce <16hex>

# verify —— 不带参数 = 全册执法（check-letter-token 主循环：信封六项/三池/令牌台账
#   咬合/白话面/跨信判据——编号唯一、日期单调、孤儿票、被复信存在性、换票配对）；
#   带文件 = 单信自检（new-letter --verify；台账按「文件所在信箱」取，--mailbox 优先）
mailbox-cli verify [--mailbox <dir>] [<信件路径>]

# gen —— 回写 README gen:pending + gen:agent-inbox 两区段 + letters-index.jsonl
#   --check-only 只查不写；--mailbox 指向主册（kfmv4 docs/ledger/agent-inbox）
#   时拒绝写入（写者分区：主册回写归 kfmv4 侧 gen-agent-inbox.mjs 独占）
mailbox-cli gen [--mailbox <dir>] [--check-only]

# scan —— 跨册欠账扫描：na 册 [NA] + 主册 [MAIN]（含 archive-v1）
mailbox-cli scan --for=清和      # 发给某职能/名字/旧线名（含「致全体」广播）
mailbox-cli scan --by=白露       # 从某名字发出（限 v2.1 信）

# reticket —— 改名换票（契约 §八改名窗口）：旧票补 revokedAt/revokeReason、
#   append 新票含 renamedFrom、信内令牌行换新 fp、文件改名（编号不变）。
#   BAR-177 判据层（白露 0010 审查四项必修+顺带项落地）：
#   入口——③写者分区闸（指向主册一律拒写，new/gen/reticket 同闸）/⑩只许换信箱
#   根目录在册信（归档区/册外拒）/④新名强制 is_v21_name（旧 ASCII 名只许在旧名
#   位置，报错指向契约 §二）/⑪新名发信人收件人入口即过名字池（生成即合规）；
#   窗口——①信头状态非 待* 或两册（--main-book，目录缺席自动跳过）有 复: <no>
#   复信即拒，--force 逃生须把 force 事实与改动内容写进 revokeReason；
#   台账——⑧ledger.errs 非空即拒/⑦与现行票比 nonce+fp（不符即拒）；
#   写盘——⑤新信→台账→删旧信改序+临时文件 rename+失败回滚（错误串写清已落盘
#   什么）/⑥信箱根 O_EXCL 写者锁（new/gen/reticket 共用，pid 探活自愈）；
#   收尾——②na 册直接回写投影（无 README 的册打印下一步提示）mailbox-cli reticket <信件路径> --new-name <新文件名> [--reason <说明>] [--force]
```

## 默认解析序

- **信箱根**：`--mailbox` > `/root/.kfm/session/信箱`（na 册）
- **名册**：`--roster` > 信箱内 `roster.json` > 主册 `roster.json`
- **状态词表**：信箱 README 规则区 > 主册 README（`合法状态词表（…）：…。` 唯一出处）
- **v1 冻结名单**：`--v1-manifest` > 信箱 `archive-v1/manifest-v1.json` > 信箱 `manifest-v1.json`
- **存量信命名前缀**：`--name-prefix`（na 册默认 `kfm-na|na`；主册用法 `kfm-na|kfmv4`）
- **名字池严格模式**：默认开；`--no-strict-pools` 或 `KFM_MAILBOX_STRICT_POOLS=0` 降级
  （仅人工排查用，同 JS）

## 与 JS 的行为差异（有意，全列）

1. **行排序**：JS `localeCompare` → Rust 字典序。本域行键是等长数字日期前缀 +
   编号，两序等价；`scan`/`gen` 输出与 JS 对表一致（主册 373 封实跑
   `gen --check-only` 绿 = 投影逐字节相同）。
2. **错误文案**：中文化重写，不逐字对齐 JS（判据与命中集合逐条对齐，
   考题咬的是判据不是措辞）。
3. **输出前缀**：`[mailbox-new]` / `[mailbox-verify]` / `[mailbox-gen]` /
   `[mailbox-scan]` / `[mailbox-reticket]`（JS 是 `[new-letter]` 等）。
4. **reticket 是新增件**：JS 侧换票是手工流程（主册 0016/0022 台账行即手工
   留痕），本器把它机械化；台账行 key 序与主册手工件逐字节同制
   （旧票尾补 `revokedAt`/`revokeReason`，新票尾挂 `renamedFrom`）。
   BAR-177 起判据层比 JS 手工流程多一层机械执法（窗口/写者分区/v21 强制/
   票面互咬/脏台账/名字池/写者锁/失败回滚/收尾投影，见上「五子命令」节）——
   JS 无对应件，谈不上差异，这是新增能力。
5. **信封日期单调判据的排序键**：JS `check-letter-token.mjs` 按 `no`
   字符串 `localeCompare` 排；本器按「编号数字段数值序 → no 字符串序」排
   （BAR-179：v2.1 编号数字段是跨分拣码共享的签发流水，next_number 跨前缀
   统一 max+1，数字序 = 签发序）。主册前缀划一时两序等价从未分歧；na 册
   NA 前缀与纯数字混排时字符串序会把后签发的纯数字信排到 NA 信前，
   把数字序单调的真册误判「日期非单调」——JS 同款潜伏病，待评审线知会
   主册同修 JS。
## 判卷（A 档）

- `crates/mailbox-core/tests/core_spec.rs` 35 题：fp golden（主册真票 6 行含
  0016 换票对 + na 册 4 行）、契约 §二文件名文法例句 + 负样本、verify 单信/
  全册各判据、gen 投影 golden 与 JS 实跑件逐字节相等、幂等、scan 广播命中、
  BAR-179 日期单调判据分拣码混排数字序钉。
- `crates/mailbox-cli/tests/cli_golden.rs` 11 题：真跑二进制——new A/B 与
  JS 实跑抄录件（`tests/golden/`）逐字节 diff、gen 回写/漂移、verify 绿红、
  reticket 全链 + BAR-177 判据钉 4 枚（窗口拒绝与 force 留痕/投影复绿/
  台账票面篡改即拒/脏台账即拒）、BAR-173 随机 nonce 真路钉。**测试不依赖
  /root/kfmv4 与 /root/.kfm**（reticket 两册扫描在钉里一律指不存在路径，
  手机也跑 chain）。
- golden 全部是 JS 实跑抄录，不许手编；变异抽检三枚（fp 截断/状态词 regex
  锚与降序/文件名发信人字数）均被考题咬死。

## 挂链

`scripts/check/mailbox.sh`（chain 第 4 步）：na 册全册 verify（词表
`kfm-na|na` + 顶层 manifest）+ gen --check-only。信箱目录不存在（手机/新
环境）自动跳过 exit 0；README 缺 gen 标记区段时 gen 道跳过（标记段就位后
自动生效）。
