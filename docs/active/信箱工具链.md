# 信箱工具链（mailbox-core / mailbox-cli）

> 2026-09-29 立。kfmv4 信箱 JS 三件套（`kfmv4/scripts/check/new-letter.mjs` /
> `check-letter-token.mjs` / `gen-agent-inbox.mjs`）的 Rust 忠实移植，
> 派活 = na 信箱 0004 号提案。分层：逻辑全在 `crates/mailbox-core`
> （纯函数零 IO——不碰文件系统、不取时间，A 档判卷）；IO 全在
> `crates/mailbox-cli`（读目录/写文件/`date` 取时//dev/urandom 发 nonce）。
> 规约唯一出处仍是 kfmv4 侧 `docs/ledger/mailbox-contract-v2.1.md`（只读引用）。

## 六子命令

```bash
cargo build -p mailbox-cli   # 产物 target/debug/mailbox-cli

# new —— 写信 + 发令牌（v2.1 模式；骨架/文件名/fp/台账行与 JS 逐字节一致）
mailbox-cli new --from-func 研究部 --from-name 清和 \
    --to 评审部白露 [--to 开发部观澜] [--to-all] \
    [--reply 0004] [--about 测试事由] \
    --type 通报 --title "标题" [--kind 征集] [--expect …] [--criteria …] [--status 待回信]
# 编号 = 纯流水号（BAR-180/契约 §八.8：本册自指码为误用——--sorting 已废止，
#   显式传非 MAIN 码硬拒；索引 sorting 由 .mailbox.json 册身份单独供，见差异 5）
# 注入口（golden/复现用）：--now-local "YYYY-MM-DD HH:MM ±HH:MM" --now-utc <ISO> --nonce <16hex>

# verify —— 不带参数 = 全册执法（check-letter-token 主循环：信封六项/三池/令牌台账
#   咬合/白话面/跨信判据——编号唯一、日期单调、孤儿票（认三栏：在册/archive-v1/
#   archive-withdrawn）、被复信存在性、换票配对；撤回票判据组（契约 §八 第 9 条，
#   BAR-193）：revokedAt 票被任何票 renamedFrom 引用 = 撤销票（配对范围取全部票，
#   两跳链首票不误判）、无人引用 = 撤回票（文件须在册三栏之一，被删红孤儿票据
#   （撤回票））、现行票 file 落撤回栏 = 半状态照红、撤回栏与在册/归档同名防重；
#   撤回件本体不参与执法）；
#   带文件 = 单信自检（new-letter --verify；台账按「文件所在信箱」取，--mailbox 优先）
mailbox-cli verify [--mailbox <dir>] [<信件路径>]

# gen —— 回写 README gen:pending + gen:agent-inbox 两区段 + letters-index.jsonl
#   --check-only 只查不写；--mailbox 指向主册（kfmv4 docs/ledger/agent-inbox）
#   时拒绝写入（写者分区：主册回写归 kfmv4 侧 gen-agent-inbox.mjs 独占）
mailbox-cli gen [--mailbox <dir>] [--check-only]

# scan —— 跨册欠账扫描：na 册 [NA] + 主册 [MAIN]（含 archive-v1）
mailbox-cli scan --for=清和      # 发给某职能/名字/旧线名（含「致全体」广播）
mailbox-cli scan --by=白露       # 从某名字发出（限 v2.1 信）

# reticket —— 改名换票（契约 §八改名窗口）：旧票补 revokedAt/revokeReason、
#   append 新票含 renamedFrom、信内令牌行换新 fp、文件改名（编号不变）。
#   BAR-177 判据层（白露 0010 审查四项必修+顺带项落地）：
#   入口——③写者分区闸（指向主册一律拒写，new/gen/reticket 同闸）/⑩只许换信箱
#   根目录在册信（归档区/册外拒）/④新名强制 is_v21_name（旧 ASCII 名只许在旧名
#   位置，报错指向契约 §二）/⑪新名发信人收件人入口即过名字池（生成即合规）；
#   窗口——①信头状态非 待* 或两册（--main-book，目录缺席自动跳过）有 复: <no>
#   复信即拒，--force 逃生须把 force 事实与改动内容写进 revokeReason；
#   台账——⑧ledger.errs 非空即拒/⑦与现行票比 nonce+fp（不符即拒）；
#   写盘——⑤新信→台账→删旧信改序+临时文件 rename+失败回滚（错误串写清已落盘
#   什么）/⑥信箱根 flock 写者锁（new/gen/reticket 共用——BAR-181 换芯，
#   原 O_EXCL fail-fast 退役，见下「写者互斥锁」节）；
#   收尾——②na 册直接回写投影（无 README 的册打印下一步提示）。
#   BAR-180 唯一改号例外（契约 §八.8 格式性勘误，白露 NA0015→0015 先例）：
#   新名 = 旧名仅去本册自指码（以 .mailbox.json 册身份为准，缺身份文件
#   fail-closed）、其余逐字节不动 → 编号同步去码，不受改名窗口限制，
#   revokeReason 必带「格式性勘误（契约 §八 第 8 条）」；此外改名不改号铁律不变
mailbox-cli reticket <信件路径> --new-name <新文件名> [--reason <说明>] [--force]

# withdraw —— 撤信 = 撤回票（契约 §八 第 9 条，BAR-193；与「撤销票/换票」严格
#   区分：无替补、台账不带 renamedFrom）。照主册共享向量
#   （kfmv4 docs/ledger/test-methods/withdraw-vectors.md，**v2**）逐条同制 JS
#   new-letter.mjs --withdraw 七步：
#   ①窗口——判据 = 事实上的零回应：两册无 复: <编号>（本册扫裸编号与自指码，
#   跨册只认全码；缺省对等册 = 主册与 na 册，--peer 覆盖；有回应拒并列出回应
#   件名与所在册）。**状态词不是判据**（白露 0034 裁，2026-09-30，起因 0052：
#   状态可以是作者自己写的处分动作，拿状态当零回应恰好挡掉最该撤的误投件）——
#   状态非 待* 时打一行注意（stderr，写明状态原文＋不作判据＋依据条号）照常
#   执行，不悄悄放行；①行打实际状态原文（不打「待*」字面）；
#   ②权限——作者自撤（--by 缺省 = 发信方）；--by 非作者须 --force（代撤），
#   代撤理由落台账「撤回票（整封作废，代撤：<X> 代 <Y>）：…」，信末署名取
#   名册 primary 职能（不取操作者自报）；
#   ③移档——git mv 进 archive-withdrawn/（只移不删；git mv -n 预演失败即拒
#   ——未 git add 的信台账不变、文件不动，不静默降级 mv）；
#   ④台账——现行票原位加 revokedAt＋revokeReason（行数不变、不带 renamedFrom；
#   台账找不到现行票即拒）；
#   ⑤留痕——信末追加「——撤回：<YYYY-MM-DD HH:MM ±HH:MM> <职能><名字>——
#   原信作废，理由：…」（撤回行之前字节与撤回前逐字节相同）；
#   ⑥投影——na 册直接重跑 gen（README 台账行带 archive-withdrawn/ 前缀＋
#   （已撤回）尾注、活信清单剔除、索引 dir:"withdrawn"）；
#   ⑦通告——代撤须另行发信通告（自撤不强制，台账即留痕）。
#   注入口（golden/复现用）：--now-local / --now-utc（同 new）
mailbox-cli withdraw <信路径> --reason "<理由>" [--by <名字>] [--force] [--peer <对等册>]
```

## 默认解析序

- **信箱根**：`--mailbox` > `/root/.kfm/session/信箱`（na 册）
- **名册**：`--roster` > 信箱内 `roster.json` > 主册 `roster.json`
- **状态词表**：信箱 README 规则区 > 主册 README（`合法状态词表（…）：…。` 唯一出处）
- **v1 冻结名单**：`--v1-manifest` > 信箱 `archive-v1/manifest-v1.json` > 信箱 `manifest-v1.json`
- **存量信命名前缀**：`--name-prefix`（na 册默认 `kfm-na|na`；主册用法 `kfm-na|kfmv4`）
- **名字池严格模式**：默认开；`--no-strict-pools` 或 `KFM_MAILBOX_STRICT_POOLS=0` 降级
  （仅人工排查用，同 JS）

## 写者互斥锁（2026-09-29，BAR-181，白露 0022 条件①）

**new / gen / reticket / withdraw 四个写者子命令共一把册级 flock**（`<信箱>/.mailbox-cli.lock`，
LOCK_EX）——信是交付面，编号 scan-then-write 的 TOCTOU 与 bar-new.sh 治的
BAR 号同族；verify/scan 纯读不占锁，gen `--check-only` 不占锁（纯查）。
闸位与调用点沿用 BAR-177 的写者分区结构（`acquire_book_lock`），本 BAR 只
换锁芯：原 O_EXCL fail-fast 退役——bar-new.sh 一次进程 new→verify→gen
连跑，fail-fast 下别线在途一封即死在半路（信开而台账未登记 = 占有丢失）。

失败模式（0022 条件③口径）：

- 拿不到锁 = **阻塞等待，不设超时**（写操作全是秒级，超时误报比等待更伤；
  与 bar-new.sh 的 flock 同款语义）；
- **无 stale 锁**：进程死亡（含 SIGKILL）内核自动放锁；
- 锁文件只建不删（防 unlink 竞态）。

钉：`crates/mailbox-cli/tests/flock_spec.rs`——互斥钉（持锁→new/reticket 必阻塞，
放锁→放行；变异锚：摘锁/收窄锁臂皆咬中）+ 并发钉（6 路并发 new 编号唯一连号）。

## 与 JS 的行为差异（有意，全列）

1. **行排序**：JS `localeCompare` → Rust 字典序。本域行键是等长数字日期前缀 +
   编号，两序等价；`scan`/`gen` 输出与 JS 对表一致（主册 373 封实跑
   `gen --check-only` 绿 = 投影逐字节相同）。
2. **错误文案**：中文化重写，不逐字对齐 JS（判据与命中集合逐条对齐，
   考题咬的是判据不是措辞）。
3. **输出前缀**：`[mailbox-new]` / `[mailbox-verify]` / `[mailbox-gen]` /
   `[mailbox-scan]` / `[mailbox-reticket]` / `[mailbox-withdraw]`（JS 是 `[new-letter]` 等）。
4. **reticket 是新增件**：JS 侧换票是手工流程（主册 0016/0022 台账行即手工
   留痕），本器把它机械化；台账行 key 序与主册手工件逐字节同制
   （旧票尾补 `revokedAt`/`revokeReason`，新票尾挂 `renamedFrom`）。
   BAR-177 起判据层比 JS 手工流程多一层机械执法（窗口/写者分区/v21 强制/
   票面互咬/脏台账/名字池/写者锁/失败回滚/收尾投影，见上「五子命令」节）——
   JS 无对应件，谈不上差异，这是新增能力。
5. **信封日期单调判据的排序键**：JS `check-letter-token.mjs` 按 `no`
   字符串 `localeCompare` 排；本器按「编号数字段数值序 → no 字符串序」排
   （BAR-179：v2.1 编号数字段是跨分拣码共享的签发流水，next_number 跨前缀
   统一 max+1，数字序 = 签发序）。主册前缀划一时两序等价从未分歧；na 册
   NA 前缀与纯数字混排时字符串序会把后签发的纯数字信排到 NA 信前，
   把数字序单调的真册误判「日期非单调」——JS 同款潜伏病，待评审线知会
   主册同修 JS。
6. **new 的 `--sorting` 废止**：JS `new-letter.mjs` 仍吃 `--sorting <码>`
   拼进编号与文件名；本器按 0020 必修①与契约 §八.8（本册自指码为误用）
   收口——编号一律纯流水号，显式传非 MAIN 码硬拒（BAR-180）。索引 sorting
   不再来自文件名，由 `.mailbox.json` 册身份供（白露册身份改动，见 §六）。

  reticket 全链 + BAR-177 判据钉 4 枚（窗口拒绝与 force 留痕/投影复绿/
  台账票面篡改即拒/脏台账即拒）、BAR-173 随机 nonce 真路钉、册身份 NA
  golden（白露 0020 §一.1）、BAR-180 钉 3 枚（new 不拼自指码/§八.8 窄例外

  golden `withdraw4_*` 四产物逐字节；阴性三例与跨册——已有回应列出

  在岗证明，v2 新③位）**；代撤落账与名册署名；未 git add 即拒不降级 mv；
  verify 判据边界——撤回件被删红孤儿票据（撤回票）/移档未撤票红半状态/
  复原绿 + 两跳换票链配对范围钉）。

  `tests/fixtures/withdraw/`，含对等册「复 MAIN0005」）。**测试不依赖
  /root/kfmv4 与 /root/.kfm**（reticket 两册扫描在钉里一律指不存在路径，

- golden 全部是 JS 实跑抄录，不许手编；变异抽检五枚（fp 截断/状态词 regex
  锚与降序/文件名发信人字数/撤回票配对范围只认现行票——两跳链假红/**回应
  扫描摘除——阴性钉红**，v2 新增）均被考题咬死。
