## 流程六段（每段：产物 / 坑 / 纪律产出）

### ① 定罪：不是没画，是旧核盖新包
- 产物：`na-stats.sh` 无 `bar_*` 字段（新核必有）→ 实锤跑的不是新核；
  `hot/libkfm_na.so` 是 8-30 22:04 的热核（6129168 字节），na-loader
  优先 dlopen hot → 新 APK 的捆绑核永无出场机会。
- 数字：旧核 uptime=255407ms；清核重启后 uptime=22542ms 且
  `bar_focused/bar_text_len` 字段出现。
- 坑：Termux 的 `am` 是包装版，**不支持 `force-stop` 子命令**；
  正解 `am start -S -n dev.kfm.na/.MainActivity`（-S = 先停后启）。
- 纪律产出：**装新 APK 必须清 hot 旧核**——deploy-phone.sh 收尾步
  内置自动清（8024 可达）；排障手册速查表 + 热更新.md §坑 双登记。
  长期正解（待办）：loader 比构建戳，hot 比捆绑旧就回落。

### ② 自验轨补齐：dump 装帧不含 chrome = 视觉轨半瞎
- 产物：首拍 na-shot 只有终端网格+光球——keybar/输入栏是「UI 私有
  装帧」不在倒帧口径里，agent 无法自验栏的视觉，只能求用户肉眼。
- 修法：dump_now 装帧补画 keybar（mods 恒 0，粘滞位无私有共享态）
  + 输入栏（读 input_bar_handle 快照，与 stats 同源）。
- 纪律产出：**凡是「状态核有共享读数」的 chrome，倒帧都必须画**——
  自验轨覆盖率 = 能自验的插件数上限。

### ③ 顺手实锤：keybar 叠层 bug（眼手错位）
- 实锤链：装帧补齐后实拍发现快捷键行第二排被输入栏盖掉——
  render_keybar 的 inset 漏叠 `input_bar::HEIGHT_PX`；触摸几何
  （android_app hit 测试）早就叠了 = **眼睛和手用的不是同一把尺**。
- 修法：render_keybar 调用 inset 改 `ime_bottom + input_bar::HEIGHT_PX`。
- 纪律产出：**渲染几何与触摸几何必须单源**——这次能抓到纯靠
  「倒帧口径 = 前台口径」的同尺对照；眼手分离的 bug 只有实拍能定罪。

### ④ 样式 v1 + 闭环验证（fba81e0）
- 产物：参考图取色复刻（渐变描边/▶发送钮/边距比例）；input_bar_spec
  12 题全绿；chain 11 步绿；热更上机；bar-inject 注入 focus/text/
  submit 全通。
- 坑：submit 后 `ai_running` 采样 8 次全 false——误判「run 没驱动」。
  真因：echo run 仅 ~0.5s，**ssh 采样（每次 ~0.4s 往返）比信号慢**；
  改机上单连接 20Hz 采样实锤 false→true(10 样本)→false 完整翻转。
- 纪律产出：**采样尺必须快于被测信号**——慢尺测快信号会冤枉好人，
  误判一次就是一轮假排障。

### ⑤ 质感 v2：读 CSS 配方，不抄截图像素（20651ee）
- 起点：用户对比后指「kfmv4 更有质感」。
- 产物：读 kfmv4 `base.css` 逐项直译七处差距——发送钮外投影+玻璃
  高光 / 聚焦紫外发光 0 0 20px / 内芯 CSS 真值近黑（v1 取成藏青）/
  135° 对角描边+左缘 3 倍粗 / 带顶渐变发丝线 / 圆角抗锯齿 / 内阴影。
  图元升级：fill_round_rect(_grad) 改 SDF 覆盖率 AA，新增
  glow_round_rect / inner_top_veil；rr_cover A 档考题 2 题。
- 性能：rr_sdf 直边快路免 hypot——全量 hypot 估算一帧多 ~百毫秒级，
  药丸键大面填充的命根。
- 纪律产出：**样式复刻的真相源是 CSS 配方，截图是合成后错觉**
  （v1 内芯取色 (18,32,56) 就是抄截图抄出的塑料蓝）。

### ⑥ 内芯渐变（efbd592）
- 起点：用户指「输入框背景有暗色渐变，na 是纯黑」。
- 实测：参考图内芯横向渐变 (29,23,57)→(12,40,54)——半透明底叠
  backdrop blur 把描边环境色晕进内芯；修法 = 内芯横向渐变，
  **取值比参考图稍沉一档**（复用 ⑤ 的塑料蓝教训）。
- 复验：na 实拍内芯 (22,24,50)→(15,32,50)，与参考图同族同幅。
- 坑：fix 提交被 check-fix-tests 连拦两次——豁免行 `tests:na` 必须
  **独占一行**（regex `^tests:na[[:space:]]*$`），后缀理由不算。

### 2026-08-31 · 长文输入尾锚（用户指认「输入很长文字看看效果」）
- 实锤：注入 50+ 字长文实拍——头部左对齐硬裁切，**正在敲的尾部
  不可见**（输入体验的死穴；kfmv4 是 textarea 自动长高+滚动）。
- 改了什么：draw_text_tail 尾锚渲染——超宽时从「刚好放得下的后缀」
  起画，左端补 … 指示头被截；截断窗口 = tail_fit_start（A 档纯逻辑，
  先红后绿 2 题钉）。占位文案仍左锚。
- 验收数字：spec_tail_fit_start_* 2 题绿；实拍长文尾部可见+… 指示。
- 纪律产出：**kfmv4 全量对齐（textarea 长高 max-height 120px）被
  有意否决**——栏长高 = 终端网格 resize = nz case-002 实锤的重绘
  洪峰传导链（resize→SIGWINCH→整史重绘）。尾锚是零几何代价解；
  若未来要真 textarea，先过「长高不触发网格 resize」设计关
  （如栏带覆盖式悬浮，网格不动）。
- **【同日被取代】** 用户随后拍板「全量复刻 kfmv4 移动端 textarea
  行为」，且设计关被「覆盖式悬浮」真解开了（见下条）——
  draw_text_tail/tail_fit_start 干净移除，本条留作演化史。

### 2026-08-31 · textarea 全量复刻（用户拍板：换行+长高+sending 图标态）
- 拍板原话：「这是需要移动端的体验的。我们做了这个ui，就是为了完全
  复刻kfmv4的行为。甚至包括点击发送按钮后的符号变化，这个也需要做。」
- 设计（过设计关的答案）：**覆盖式悬浮**——栏带/keybar 随行数向上
  浮盖终端底部行，终端网格几何永远只让单行带高（220px）。长高不
  触发 resize→SIGWINCH→重绘洪峰链（上条的否决条件就此解除）。
  几何参数：MAX_LINES=3，LINE_STEP=63px（kfmv4 font 14CSS≈42 物理
  ×1.5 行高），带高 220/283/346；字号恒定 ~40px 不随行高缩。
- 眼手同尺单源：渲染层（termview 有字体）量宽折行（wrap_starts 贪心
  断行，A 档考题钉）→ bar_text_lines → set_lines 写回状态核——
  触摸命中/渲染/dump 读同一份行数。超 MAX_LINES 尾锚显最后 3 行
  （手动滚动 = 记下的缺口）。
- sending 图标态：kfmv4 `.ai-send-btn.sending` ▶ ↔ ⏸ 硬切，跟
  ai_running 走；前台 rasterize 与后台 dump 同尺（⏸ = 双竖圆角矩形）。
- **BAR-039（自验轨实拍定罪）**：挂起态注入 55 字长文，dump 画出
  3 行文本但栏带仍单行高（第三行溢出文本区）——渲染带高读的
  snap.lines 是 poll 转写写回，后台无 poll = stale，同帧文本实测
  3 行/带高 stale 1 行 = 两张皮。修法：render_inputbar 自带量宽
  折行（画文本本就要量，一次量两头吃），带高从实测派生；
  rasterize/dump 的 keybar inset 同步实测。snap.lines 只服务触摸。
- 验收数字：新考题 7 道全绿（wrap_starts×2 / height_for_lines×2 /
  bar_text_lines×2 / bar039 回归钉×1）；chain 11 步绿；热更 vc3
  上机冒烟 3/3；实拍三连——①挂起态注入长文：带高=3 行、文本全收
  在文本区内、keybar 随栏上浮（BAR-039 同尺复验过）；②orb-inject
  run → 发送钮 ⏸ 实拍命中；③end+clear → 复原单行 ▶。
- 纪律产出：**眼手同尺要落到「所画即所量」**——经手转写的读数
  （poll 写回 lines）在写回链路缺席时（后台/挂起）必然两张皮；
  凡是渲染几何，能从原料实测就绝不读转写。
