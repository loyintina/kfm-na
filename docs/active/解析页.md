# 解析页设计（两轴插件契约）

> 状态：**宪法 v2（2026-09-21：§四 三区排布改版 + ④ 服务/连接卡
> 本地相 B 案拍板；初版 2026-09-20 用户拍板两轴原则）**。解析页
> （终端右侧滑出的解析器页）的唯一设计来源。动解析页结构/加卡/
> 加终端前必读。
>
> 一句话：解析页 = **当前对象 × 已注册插件卡** 的装配结果——对象轴
> （Endpoint）与能力轴（插件卡）正交，互不感知对方存在。

## 〇、由来（为什么是两轴）

用户 2026-09-20 拍板的两条适配律：

1. **新终端律**：未来接入其他终端（不止服务器/本地），现有卡不许改；
2. **新功能律**：未来增加新功能卡（不止现有三张），现有终端不许改。

两相 if/else 在第三个终端进来时就是灾难，故两轴从第一天就是注册表，
不是分支。规格原型照抄 nz 移交的 `plugin-contract.md`（契约签名/
脑皮分离/槽位唯一主人/清单外状态即 bug），Rust 本地化。

## 一、通用设计标准（宪法定位回顾）

手机屏幕三主框：**中央是对象主体，左侧是路由（切换中央对象），右侧
是解析器（解析中央对象）**。解析页因此不自己维护「显示哪一相」的
开关——**中央终端当前连着谁，就解析谁**（跟随 `session_router` 与
设置页 terminal.json 裁决的当前对象）。光球（上侧）与配置页（右侧
齿轮入口）是全局件，不在本契约范围。

## 二、对象轴：Endpoint（数据源提供方）

每个终端对象实现同一组**能力面**；能力给不出 = 显式 None，插件卡
据此进降级相，不许对象假装能给。

| 能力 | 服务器相现状 | 本地相 | 未来 N 终端 |
|------|------------|--------|------------|
| `exec(命令) → 输出` 短命执行通道 | ws exec 跑 tmux 命令（tmux_exec） | local PTY exec（exec_probe 已证可行） | 各自传输 |
| `sys_info() → Option<SysInfo>` 体征 | HTTP 轮询 /api/na/sys（svc_health） | `na_sys::collect("/data")` 直读 | 各自采集 |
| `health() → 会话清单` | HTTP /api/na/health | 本地 PTY/进程表 | 各自协议 |
| `link_snap() → 链路状态` | tunnel::snap()（隧道即链路） | 恒在线（回环） | 各自链路 |
| `display_word() → 对象词` | settings 里的服务器名 | 「本地」 | 自报 |

决策记录（2026-09-20）：**Exec / Query 两条腿，不统一单入口**——
tmux 卡吃短命执行通道、环境/服务卡吃轮询快照，数据面本不同构，
贴现状抽象，不为对称而对称。

对象轴的注册机制复用 **cordis-na `Plugin`/`ServiceKey`**（
`conn_provider_ws`/`conn_provider_local` 已是毛坯）：Endpoint 作为
服务注册，插件卡按 ServiceKey 寻址当前对象。

## 三、能力轴：插件卡（声明契约 + 自渲染）

每张卡 = nz 契约签名的网格涂装版：

- **id + 数据契约声明**：「我需要 SysInfo / 会话表 / 链路快照」——
  只认数据类型，不认来源（HTTP 还是 /proc 与卡无关）；
- **脑/皮分离**（现状已是）：`ui/*_card.rs` 文案合成纯函数 = 脑，
  termview 涂装段 = 皮，layout/hit = 几何；
- **自报高度** `card_h()`：排布器不问卡的内部账；
- **动作意图**：重排/新窗/重连 = 卡发意图，经当前对象的 exec 通道
  执行——卡不直连传输层；
- **降级显形**：对象给不出契约数据时，卡进自声明的降级相
  （「—」/「本对象不支持」占位），降级形态写进契约，不许各卡
  现场发明；清单外状态 = bug（nz §7 思想）。

## 四、三区排布器（槽位层；v3 2026-09-21 午后用户拍板放宽）

v1（2026-09-20）= 竖链 + 单页滚动，已收编为 `parser_chain.rs`。
v2 用户拍板（「tmux 竖排放右下角常驻……保证右滑后直接手指能点到
切换」）改版为**三区**。立法理由：排版服从操作频率——tmux 切换是
解析页唯一高频动作，其余卡都是「看一眼」的只读信息；右下 = 单手
握持拇指热区，高频动作钉热区常驻，「右滑→点窗口」恒定两步。
v3 用户拍板（同日午后，v2 真机观感回炉）：「放宽 UI 到能正常
显示那些长字……还是占半屏合适」——右列定宽废、改**屏宽比例**；
「按钮不要做横排，本来就窄，并排两个更窄」——tmux 卡钮竖排；
「弹起后右上区域做卡片的压缩、里面内容的滑动，不要做卡片的
滑动」——右上区纵向受压时卡框钉区顶压缩、内容卡内滚；
「要做光球的横向避让，把 tmux 窗口让出来」——光球让位条款。

- **区域划分**：页面分两竖列——**右列 = 屏宽 1/2**（v3：比例制，
  网格对齐取整；实现参数 `COL_W_NUM/COL_W_DEN` 单常量，约束 = 字段
  标签+长值（IP:端口级）一行放下不折行；v2 的 16 格定宽已废——
  窄列折行叠字是真机观感事故）；**左区 = 剩余全部宽度**。右列再分两段：
  **右下常驻区**（tmux 卡竖排 1×N，钉视口底，**钮竖排一行一钮**）+
  **右上滚动区**（连接·服务合并卡——通联状态与 tmux 是「操作 +
  状态」的天然配对）。左区 = 一个滚动区（环境卡 + 未来新卡）。
- **常驻语义**：tmux 卡永不被滚出屏。卡自身维持既有上限（6 窗）+
  内部滚动；常驻区高度 = 卡自报高，封顶视口（超高内滚）。
- **右上压缩律（v3）**：右上区窗高度充裕时卡自报高平铺；区窗受
  压（键盘弹起等）时**卡框钉区顶、高度钳进区窗**，溢出内容走
  卡内滚动——卡框永不被整卡滑出屏（与 tmux 卡内滚同语言：
  框不动、内容动）。
- **光球避让（v3）**：解析页滑入时，光球横向让出右列——避让量
  跟页滑入度同步（页进多少球让多少，同一份缝采样）；球渲染与
  命中同吃避让后坐标（眼手同尺）。页推回球归位。
- **滚动分流**：垂直拖拽按落点 x 命中分流——落左区滚左账，落右上
  区滚右上卡内账，落常驻区喂 tmux 卡内滚动；两本滚动账各自独立
  钳制（v1 page_scroll 钳制语义逐份继承）。三区同吃
  bottom_inset（BAR-120 线视口化契约不变：区底 = 输入栏带以上）。
- **卡内动效归合成期（v3 附则，环境卡柱轨定案）**：卡的常驻内容
  随槽烘焙（采样换代才重烘）；**连续位移类动效**（如环境卡柱轨的
  采样滑入）另拆小层，在合成期以源 uv 窗口平移呈现——逐帧重烘
  整页层是 13MB 上传级的回潮（BAR-096/097/100 家族纪律，2026-09-21
  环境卡重做落第一例：`ChromeSlot::SysBars` + `sys_card::band_place`）。
- **卡的归属**：卡→区 = 注册表静态声明（槽位属性）。卡对排布零
  感知原则不变——不 import 邻卡常量、不问自己排第几、不知道自己
  在哪个区；自报高度 `card_h()` 契约不变。
- **排布器输出**：三区几何（左区窗 / 右上区窗 / 常驻槽）+ 两本
  滚动账唯一源；卡侧 `layout_in` 排布器配给制签名不变，v1 四笔账
  （slot_top/chain_bottom/reserved_below/slot_rect）按区重组。

## 五、试金石与破例律

**现有三卡作为首批插件迁入**（行为零变化，既有钉全保）是设计对错
的试金石：迁进去不需要为任何一张卡破例 = 轴切对了；要破例 = 轴
切错了，当场返工契约，不许带病前进。
