# 解析页设计（两轴插件契约）

> 状态：**宪法初版（2026-09-20 用户拍板两轴原则）**。解析页（终端右侧
> 滑出的解析器页）的唯一设计来源。动解析页结构/加卡/加终端前必读。
>
> 一句话：解析页 = **当前对象 × 已注册插件卡** 的装配结果——对象轴
> （Endpoint）与能力轴（插件卡）正交，互不感知对方存在。

## 〇、由来（为什么是两轴）

用户 2026-09-20 拍板的两条适配律：

1. **新终端律**：未来接入其他终端（不止服务器/本地），现有卡不许改；
2. **新功能律**：未来增加新功能卡（不止现有三张），现有终端不许改。

两相 if/else 在第三个终端进来时就是灾难，故两轴从第一天就是注册表，
不是分支。规格原型照抄 nz 移交的 `plugin-contract.md`（契约签名/
脑皮分离/槽位唯一主人/清单外状态即 bug），Rust 本地化。

## 一、通用设计标准（宪法定位回顾）

手机屏幕三主框：**中央是对象主体，左侧是路由（切换中央对象），右侧
是解析器（解析中央对象）**。解析页因此不自己维护「显示哪一相」的
开关——**中央终端当前连着谁，就解析谁**（跟随 `session_router` 与
设置页 terminal.json 裁决的当前对象）。光球（上侧）与配置页（右侧
齿轮入口）是全局件，不在本契约范围。

## 二、对象轴：Endpoint（数据源提供方）

每个终端对象实现同一组**能力面**；能力给不出 = 显式 None，插件卡
据此进降级相，不许对象假装能给。

| 能力 | 服务器相现状 | 本地相 | 未来 N 终端 |
|------|------------|--------|------------|
| `exec(命令) → 输出` 短命执行通道 | ws exec 跑 tmux 命令（tmux_exec） | local PTY exec（exec_probe 已证可行） | 各自传输 |
| `sys_info() → Option<SysInfo>` 体征 | HTTP 轮询 /api/na/sys（svc_health） | `na_sys::collect("/data")` 直读 | 各自采集 |
| `health() → 会话清单` | HTTP /api/na/health | 本地 PTY/进程表 | 各自协议 |
| `link_snap() → 链路状态` | tunnel::snap()（隧道即链路） | 恒在线（回环） | 各自链路 |
| `display_word() → 对象词` | settings 里的服务器名 | 「本地」 | 自报 |

决策记录（2026-09-20）：**Exec / Query 两条腿，不统一单入口**——
tmux 卡吃短命执行通道、环境/服务卡吃轮询快照，数据面本不同构，
贴现状抽象，不为对称而对称。

对象轴的注册机制复用 **cordis-na `Plugin`/`ServiceKey`**（
`conn_provider_ws`/`conn_provider_local` 已是毛坯）：Endpoint 作为
服务注册，插件卡按 ServiceKey 寻址当前对象。

## 三、能力轴：插件卡（声明契约 + 自渲染）

每张卡 = nz 契约签名的网格涂装版：

- **id + 数据契约声明**：「我需要 SysInfo / 会话表 / 链路快照」——
  只认数据类型，不认来源（HTTP 还是 /proc 与卡无关）；
- **脑/皮分离**（现状已是）：`ui/*_card.rs` 文案合成纯函数 = 脑，
  termview 涂装段 = 皮，layout/hit = 几何；
- **自报高度** `card_h()`：排布器不问卡的内部账；
- **动作意图**：重排/新窗/重连 = 卡发意图，经当前对象的 exec 通道
  执行——卡不直连传输层；
- **降级显形**：对象给不出契约数据时，卡进自声明的降级相
  （「—」/「本对象不支持」占位），降级形态写进契约，不许各卡
  现场发明；清单外状态 = bug（nz §7 思想）。

## 四、卡链排布器（槽位层，新建共享层）

现链底账写死在 `parser_page.rs` layout_vp（三卡顺序 + 高度常量互相
import）——插件化后收编为**排布器**：

- 输入 = 注册卡列表（有序）× 各卡自报高度；
- 输出 = 链式几何 + 页面滚动窗（layout_vp 的 page_scroll 机制上移
  到排布器，钳制语义不变）；
- 卡对排布零感知：不 import 邻卡常量，不问自己排第几。

## 五、试金石与破例律

**现有三卡作为首批插件迁入**（行为零变化，既有钉全保）是设计对错
的试金石：迁进去不需要为任何一张卡破例 = 轴切对了；要破例 = 轴
切错了，当场返工契约，不许带病前进。

## 七、明确的非目标

- 不做插件热加载/动态下发（注册表编译期静态，cordis-na PluginEntry
  启动配置表已够）；
- 不做卡的用户自定义排序/显隐（排布器有序列表是代码常量，未来有
  需求再议）；
- 文件树页（左滑）不在本契约——它是路由位不是解析位，解冻时另议。
