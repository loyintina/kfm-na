# 热更新（loader/核心分离，2026-08-26 与用户定）

## 目标

改代码不再重打 APK、过安装器、手动点装：核心 `.so` 直接推进沙箱，
重启 App 即生效。这是插件化的同根路——壳与核心之间只隔一层
dlopen + 固定入口符号，壳就是插件宿主胚胎（未来核心用同一机制
加载功能插件 .so，cordis-na 插件运行时的原生面）。

## 结构

```
APK(出厂焊死,设计目标永不变)
└── lib/arm64-v8a/
    ├── libna_loader.so   ← manifest lib_name 指它(极小,只做选择+转发)
    └── libkfm_na.so      ← 捆绑核心(回落用,保底包永远自包含)
沙箱(热更落点)
└── {files}/hot/libkfm_na.so  ← na-push-so.sh 推到这里
```

na_loader 的 `ANativeActivity_onCreate` 做且只做：

1. `{files}/hot/libkfm_na.so` 存在且 `dlopen` 成功 → 用热更核心；
2. 否则 → `dlopen("libkfm_na.so")` 回落包内捆绑核心（裸 soname 走
   框架命名空间搜索路径，`extractNativeLibs=false` 直映射也能解析）;
3. 每次选择落档 `{files}/usr/tmp/loader-pick`(`pick=hot|bundled
   why=...`)——**跑的是谁必须可查**，回落原因不许靠猜；
4. `dlsym` 真 `ANativeActivity_onCreate` 转发，壳退场。

**JNI 转发层（BAR-039,2026-08-26 补上）**：壳除了 Activity 入口还导出
三个 IME 符号（`nativeCommitText/nativeSendKey/nativeImeLog`），原样
tail-call 进当前核心。原因：Java 的 native 方法按 `loadLibrary` 的
库名绑定实例——绑到包内捆绑核心就会和 hot/ 运行核心裂脑（IME 落字进
捆绑副本的静态队列，运行核心永远抽不到，输入全灭）。所以 Java 焊死
`loadLibrary("na_loader")`，换核 Java 无感。教训：**任何按库名绑定的
跨层入口，热更/插件化后都要审实例归属**。

**热更的边界**：只有核心 `.so` 可热更。Java/dex（KfmImeView 等）与
loader 壳焊死在 APK 里，改了它们就要重打包过安装器（BAR-039 这次就是
——两类改动都沾了）。改之前想清楚归哪层。

## 链路

```bash
# 服务器侧一键(手机仓已编好 release 核心时):
bash scripts/na-push-so.sh          # 从手机仓拿 .so 推入 hot/
# 之后自动重启(na-push-so.sh 默认联动 na-restart.sh;--no-restart 可关)
# 判卷:
ssh -p 8024 ... cat .../usr/tmp/loader-pick   # pick=hot
# boot 报告构建戳与推送的构建一致
```

## 边界与纪律

- **免重装 ≠ 免重启**：进程内热替换事件循环不现实（winit 单 EventLoop
  铁律，BAR-037 咬过）。重启路径已通车（2026-08-26）：restart-req
  通道体面退出 + BAR-037 重跑防御 + na-restart.sh 一键闭环
  （见 docs/active/调试闸门.md §二）。
- 合法性：私有目录 dlopen 与 exec 同一张通行证 = targetSdk 28 域
  （BAR-024，沙箱跑 sshd/bash 靠的也是它）。换 targetSdk 必须先过这关。
- 观测：loader-pick 落档失败静默（同观测铁律）；核心全灭（捆绑都
  dlopen 失败）= 不转发入口，活动自然终结，loader-pick 留遗言。
- 考题：tests/loader_spec.rs 3 道（路径拼接/回落顺序/落档格式）。

## 坑：装新 APK 必须清 hot/ 旧核（2026-08-31 实锤）

loader 永远优先 hot/——**hot 里躺着旧核时，新 APK 白装**（包内捆绑
新核永无出场机会）。症状：装了带新功能的包却看不到新功能，stats
字段族对不上版本。当日实锤链：输入栏已上线的 APK 装后无输入栏，
stats 无 bar_* 字段，hot/libkfm_na.so 是前一天的热核。

处置（deploy-phone.sh 收尾步已内置，8024 可达即自动清）：

```bash
# 手动版(8024 进沙箱):
rm -f /data/data/dev.kfm.na/files/hot/libkfm_na.so   # 清旧核,回落包内新核
# 或直接推同版新核盖住:
bash scripts/na-push-so.sh <新编.so路径>
```

长期正解（待办，未做）：loader 比构建戳——hot 核比包内捆绑核旧就
无视 hot 回落捆绑。在 na-loader 加一道时间戳比较即根除本坑。
