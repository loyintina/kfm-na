# 热更新（loader/核心分离，2026-08-26 与用户定）

## 目标

改代码不再重打 APK、过安装器、手动点装：核心 `.so` 直接推进沙箱，
重启 App 即生效。这是插件化的同根路——壳与核心之间只隔一层
dlopen + 固定入口符号，壳就是插件宿主胚胎（未来核心用同一机制
加载功能插件 .so，cordis-na 插件运行时的原生面）。

## 结构

```
APK(出厂焊死,设计目标永不变)
└── lib/arm64-v8a/
    ├── libna_loader.so   ← manifest lib_name 指它(极小,只做选择+转发)
    └── libkfm_na.so      ← 捆绑核心(回落用,保底包永远自包含)
沙箱(热更落点)
└── {files}/hot/libkfm_na.so  ← na-push-so.sh 推到这里
```

na_loader 的 `ANativeActivity_onCreate` 做且只做：

1. `{files}/hot/libkfm_na.so` 存在且 `dlopen` 成功 → 用热更核心；
2. 否则 → `dlopen("libkfm_na.so")` 回落包内捆绑核心（裸 soname 走
   框架命名空间搜索路径，`extractNativeLibs=false` 直映射也能解析）;
3. 每次选择落档 `{files}/usr/tmp/loader-pick`(`pick=hot|bundled
   why=...`)——**跑的是谁必须可查**，回落原因不许靠猜；
4. `dlsym` 真 `ANativeActivity_onCreate` 转发，壳退场。

## 链路

```bash
# 服务器侧一键(手机仓已编好 release 核心时):
bash scripts/na-push-so.sh          # 从手机仓拿 .so 推入 hot/
# 之后重启 App(划掉重开;自动重启通道 na-restart 押后做)
# 判卷:
ssh -p 8024 ... cat .../usr/tmp/loader-pick   # pick=hot
# boot 报告构建戳与推送的构建一致
```

## 边界与纪律

- **免重装 ≠ 免重启**：进程内热替换事件循环不现实（winit 单 EventLoop
  铁律，BAR-037 刚咬过）。重启路径可靠性归 BAR-037 + 未来的
  restart-req 通道管，不在本文范围。
- 合法性：私有目录 dlopen 与 exec 同一张通行证 = targetSdk 28 域
  （BAR-024，沙箱跑 sshd/bash 靠的也是它）。换 targetSdk 必须先过这关。
- 观测：loader-pick 落档失败静默（同观测铁律）；核心全灭（捆绑都
  dlopen 失败）= 不转发入口，活动自然终结，loader-pick 留遗言。
- 考题：tests/loader_spec.rs 3 道（路径拼接/回落顺序/落档格式）。
