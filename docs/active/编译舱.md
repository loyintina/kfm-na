# 编译舱 — na 自持编译+热更链（living，2026-09-23 立项）

> 用户拍板（2026-09-23）：「未来我启动旧手机，工具链等等还需要在那边开一个
> 完整的测试，那时候就需要 na 拥有自己的编译热更新链路，陌生的设备可没有
> 我们现在的 termux 资产。」本档是该项唯一设计源。

## 背景

- 2026-09-23 日常闸已收归服务器全天（AGENTS.md 跨线运维公约 1 修订，
  pre-commit 全天本地 chain，chain-phone 降级可选）——日常开发不再依赖
  Termux 资产。
- 但「在一台陌生设备上从零立起开发能力」仍无自举路径：工具链、依赖源、
  编译、热更全靠现成 Termux 环境。旧手机开机即此场景。

## 目标（验收判卷）

陌生设备（只装 na APK + 服务器可达）走通：

```
装 APK → 9022 通联 → 拉工具链包 → 拉源码 → 编出 libkfm_na.so
→ 热更换装 → 重启 na 生效
```

判卷 = 旧手机开机实测全链（C 档，实拍为凭）。这就是本项的终验收。

## 范围边界

- **舱内只编 Rust 核**：产出物 = 可热更的 `libkfm_na.so`（热更通道已有：
  hot/ 原子换装，BAR 系列成熟路径）。Java 皮变更极少且 APK 安装本来要
  人工点确认，不在舱内。
- 完整 chain（javac/aapt2/打包步）留在服务器与现有手机 Termux；舱内
  只保证「编得出 .so」+ 装完能自启（na 自己就是 smoke 探针）。

## 工具链包

- 内容：Termux 官方 rust + clang（aarch64 host → aarch64-linux-android
  target）+ **cargo vendor 依赖源**（离线可编，设备不需要碰 crates.io）。
- 服务器侧打包：`scripts/pack-toolchain.sh`（待写）——解 termux .deb →
  prefix 重定位 → tar.zst → 落固定取包点。
- 体积预算：待 spike 实测（估压缩后 0.5~1GB）。

## 通道与落点

- 传输：9022 通道（`scripts/lib/na-ssh.sh` 全家，na 自持反连），大文件
  直接 `scp -P 9022`。
- 落点：na 私有目录 `files/` 下——exec 已放行（targetSdk 28 域降级，
  L3 实证）。工具链解压到 `files/toolchain/`，源码仓 `files/src/kfm-na/`。

## 驱动形态（分两版）

- **v1（文档+手敲）**：na 本地终端已有本地 PTY，按本档命令序列手跑通。
- **v2（解析页插件卡）**：走解析页插件契约（docs/active/解析页.md）加
  「编译舱」卡：工具链在不在/源码版本/一键编/构建日志尾/热更换装钮。
  v2 依赖插件契约适配新终端的既有挂账，不催。

## Spike（动工前必须先跑，数据回填本档）

1. 手机 Termux 里冷编 kfm-na release：耗时 / 峰值内存 / target 目录体积
   ——决定旧手机能不能扛（扛不住则降级，见风险）。
2. `cargo vendor` 离线编验证：断网（或 --offline）冷编一把过。
3. 工具链包重定位后在 na 私有目录 exec 冒烟：`rustc --version` + hello
   世界链接运行。

## 风险与降级

- **老设备性能/存储/发热**：spike 1 数据说话。若真扛不住全量编，降级
  方案 = 服务器编好 .so、设备只热更——但那 9022 已够，本项价值退为
  「可选冗余」，不强求。
- SELinux / 私有目录 exec 限制随 Android 版本漂移： spike 3 先探。
- vendor 全量依赖的体积与更新成本：每次 Cargo.toml 变动要重打包，
  接受。
