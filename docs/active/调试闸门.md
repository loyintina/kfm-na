- **注入**:服务器本机 `ss -K` 掐断 8021 已建立 ws 连接（=网络断开,
  契约守护的真实触发器;服务端代码零接触,红线不越）。
- **判五步**:deaths 记账 +1 → 活跃侧不受扰（仍 local）→ 8021 自愈
  重连（传输层自动重连,远程复活为新会话）→ 全程 local 回显正常。
- **一生一发锁存**:待机死亡记账后在进程生命周期内锁存——同进程
  再掐 ws 无第二枚事件（远程变僵尸条目,切换重连后重置）。marker
  （na.pid）同进程跳过,重启/热更自动重新武装。
- **阴性对照知识（重要,勿复用旧路线）**:杀 node 下的 tmux attach
  客户端**不产生**死亡事件——服务端对 attach 层死亡不上报,death
  的定义=ws 断开。v1/v2 路线作废实录在脚本 git 史。
- **已知缺口**:Ctrl-] 切换为 UI 层有意留白——「活跃=远程时死亡
  自动重孵」半边契约留人工验证。

### 探针③ PIN-remote-active-death（2026-08-28,活跃=远程死亡自动重孵契约）

- **注入**:switch-req 切活跃到远程 → 服务器本机 `ss -K` 掐 8021 ws
  ——远程作为**活跃方**死亡（通道九解锁的正是这半边）。
- **判五步**:deaths +1 → active **保持 remote**（自动重孵不换名）→
  重连横幅 → 新 shell 回显 → 全程 local 不受扰。
- **可重复**:每次运行=真实一次断网重孵,无锁存（与待机半边的
  一生一发不同——活跃死亡有自动重孵,天然可复验）。
- **运行代价**:弹一次远程会话（重孵=新 shell;amp tmux 现场无损）,
  宜在远程空闲时跑。
