# 工具卡 —— 工具调用 = 一等 UI 对象

> 2026-08-13 立（用户设计讨论定方向）。状态：**四个待拍板项未定，未定前不准实现**。

## 一、概念

AI 调用一个工具，屏幕上就真实地发生这件事：

- AI 调 `edit` → 终端回显动作流水，文件树弹出该文件的小卡，
  光标（原子手）在卡上播放编辑动画
- AI 调 `grep` → 弹出结果小卡，光标做动态交互
- **双向可用**：人也能召唤同一张卡用 AI 的工具——grep 卡 = 搜索框 + 结果列表，
  edit 卡 = diff 视图。工具层是 AI 和人共用的 API：
  AI 的接口是工具 schema，人的接口是小卡，后端是同一个

这不是 kfmv4 卡片堆的继承，是替代：kfmv4 的卡是被动观察窗（日志/终端），
工具卡是**动作的实体化**。

## 二、原子手 = 动作回放光标

kfmv4 的原子手（hand.ts，状态机 + 玻尔皮肤）在 NA 找到本职工作：
AI 动手时它移动/按下播给你看，人动手时走同样的手势管线。
一条动作总线：工具调用 → ws 广播动作事件 → 客户端弹卡 + 手移动 + 播动画。

## 三、动作事件协议（草案，实现前冻结）

服务端已有 ws 广播（kfmv4 hand-move/hand-press 在跑）和 tool-exec 流水。
事件形态：

```
tool-call: { seq, tool, summary, target? }   # summary = 命令/路径/查询要点（≤60 字符）
  # target 按工具定：edit/write/read → 文件路径；grep/glob → 查询串；bash → 无
```

edit/write 动画素材直接在工具输入里（路径 + old/new 字符串/diff），
客户端播动画**不需要重读文件**。

## 四、工具 → 卡映射表（草案）

| 工具 | 卡 | 说明 |
|------|----|----|
| bash | 无卡 | 卡就是终端本体——命令本来就在屏幕上滚 |
| edit / write | 文件卡（diff 动画） | 高亮行 + 打字机式 diff 播放 |
| grep / glob | 结果卡 | 结果列表，手可点 |
| read | 【待拍板·建议静默】 | 高频低信息量，弹卡会吵死 |
| 其他 | 逐一定义 | 加新工具 = 此表加一行 |
