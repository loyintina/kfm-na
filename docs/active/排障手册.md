## 环境与前置(先读,盲测洞①②补)

- **所有 `na-*.sh` 都在服务器上跑**,CWD = `/root/kfm-na`(脚本内
  路径相对仓库)。不要在手机 Termux 里跑它们。
- **前置一:kalo 隧道活着**。na-*.sh 全部经 `ssh -p 8024 localhost`
  进 na 沙箱,8024 是 kalo 反隧吊着的手机侧端口。先探:
  `nc -z localhost 8024`(通 =  exit 0)。不通 → `kalo status` 看
  死因(kalo-ssh.log),或请用户点开 na 图标。8022 = Termux
  (编译/部署用),8024 = na 沙箱(观测/注入用),别混。
- **前置二:探针钥匙** `/root/.ssh/na_probe_key`(脚本内已写死,
  存在即可,无需操作)。
- **前置三:na 进程活着**。8024 通但无应答 → `na-restart.sh` 拉回;
  熄屏/锁屏时 am start 可能被系统挡,那时请用户手动点图标。
- **闸门目录(沙箱内绝对路径)**:
  `/data/data/dev.kfm.na/files/usr/tmp`——panic.log / trace.txt /
  stats-res / loader-pick / flight-rec.bin 等档案都在这。
  手册正文凡写 `$NA_TMP` 即此路径(脚本里写死,手动 ssh 进去
  翻档案时用)。
- **field-reports.log** 在服务器 `/root/kfm-na/`(report 通道的
  落点),grep 中文记得加 `-a`。boot 行格式:
  `[boot] android_main 进入 (构建 <短hash>-<戳> · vc<epoch>)`。

## 一、闪退/打不开

1. `bash scripts/na-autopsy.sh <现象词>` 一把收齐(它自己会触发
   trace/stats 落盘再拉回八件档案)。
2. `panic.log` 有末行 → 行内 at= 直指文件行号,msg= 是断言内容;
   `panic-trace.txt` 是同案死前 64 行事件流。
3. panic.log 干净 → 看 field-reports.log(`/root/kfm-na/`,grep 加 -a)
   有没有 `[boot] android_main 进入 (构建 <戳>)`:
   - 连 boot 行都没有 = 死在 native 之前(loader/Java/dex 层,
     回忆 BAR-011/013 的 .so-dex 错配链);
   - 有 boot 行但用户说闪退 = 死在建窗/建表面段,看 trace.txt 尾部。
4. **对构建戳**:boot 行的短 hash 必须等于本地 `git rev-parse --short HEAD`,
   不等 = 设备跑的不是你想的那个核心(热更没上位,查 loader-pick)。

## 二、黑屏/画面不动

1. `bash scripts/na-ping.sh`:
   - `background` = 在后台,看门狗休假,不是病(BAR-036 前台门控);
   - `stall beat_age=Nms` = 事件循环真卡死 → `loop-stall.log` 有迁移档,
     `na-trace.sh` 看卡死前最后事件;
   - `alive` = 循环活着 → 病在渲染/内容,转第三条。
2. 循环活着但屏黑:`na-shot.sh` 拍图 vs `na-text.sh` 读屏对照——
   text 有内容 shot 全黑 = 渲染路径病;text 也空 = 会话/泵病
   (stats 看 pump_calls 涨不涨)。

## 三、输入类(打字没反应/键盘弹不出)

1. **分流第一刀**:`na-type.sh 'ls\r'` 直注 PTY(绕过 IME 全链),
   `na-text.sh` 读屏看执行没有。
   - 注入有效 = 病在 IME 链路(键盘/组词/JNI 绑定),往下走;
   - 注入无效 = 病在闸门 keys-in 或会话本身,`na-trace.sh` 看 gate 段。
2. IME 链路判据:`na-stats.sh` 的 `keys/keys_bytes` 注入后必须涨;
   trace 的 `ime` 段看 commit 计数(BAR-039 裂脑案的判据:
   键盘弹得出但 commit 恒 0 = IME 绑错库实例,loader 转发层已根治,
   回归先查 loader-pick 是不是 bundled 旧核心)。
3. 键盘弹不出:trace 找 `[java] IME 占位已叠加, focus=`——
   没有这条 = Java 皮没起来(重打 APK 层的事);有但 focus=false
   = 焦点案(BAR-009/012 家族史)。

## 四、显示类(方框/错位/里倒歪斜)

1. `na-shot.sh` 拍图亲眼确认(拉到 /tmp/na-shot.png,ReadMediaFile 看)。
2. `na-trace.sh | grep tofu` 看目击名单:哪个码位缺字形——
   子集补丁表(font-bake.py)加码位或借形(BAR-027/028 流程)。
3. 布局错位类(间距/裁剪/双宽):`na-replay.sh` 拉回飞行记录仪在
   host 回放,末屏与 na-text 逐行 diff;考题进 tests/termview_spec.rs
   (BAR-025/026 都是这么钉的,都带变异抽检)。

## 五、手势类(滚动/缩放/长按选择)

**触摸注入通道已通车（2026-08-27，通道八）**——手势 bug 全闭环：
1. `na-touch.sh 'scroll 3'` / `'tap x y'` / `'down x y' 'sleep 600'
   'up x y'`（长按）注入复现，与真手指同一 handle_touch 入口；
2. `na-text.sh` / `na-shot.sh` 对照结果（scroll 后读屏首行应变；
   选区高亮拍图亲验）;
3. stats 的 `touches` 字段确认注入落地计数。
修复后同尺复验：同一注入脚本再打一遍。写复现脚本时直接进
`scripts/cases/BAR-xxx-repro.sh`(na-case.sh 模板已留位)。

## 六、启动慢 / 趋势类(「越来越慢」「越来越卡」)

**单次快照判不了趋势——先采样成序列,再看斜率**(盲测洞③补)。

1. **启动慢**:`na-trace.sh` 的 boot/conn 段自带「距 android_main
   毫秒数」,段间差就是归因(BAR-020~023 家族:字体探测/同步直报/
   冷连接都已销,新慢先看有没有新大头段)。趋势判据 = **多次冷启动
   对比**:`bash scripts/na-restart.sh` 连跑 3 次,每次
   `na-trace.sh` 摘 boot 段总耗时,序列上涨才坐实「越来越慢」。
2. **运行期变慢/变卡**:连拍求差速率——
   ```bash
   for i in $(seq 1 10); do bash scripts/na-stats.sh | grep -E 'cpu_jiffies|rss_kb|pump_calls|draw_avg'; sleep 3; done
   ```
   `cpu_jiffies` 差分 = CPU 速率(jiffies/3s);`rss_kb` 单调上涨
   = 泄漏嫌疑;`pump_calls` 高速空转 = 泵病(57k/s 案的判法)。
3. **结案判据**(逃逸条款):趋势类不许凭「修完拍一张看着正常」
   结案——修复前后各采一组同窗序列,斜率对比写进案卷判卷法栏。

## 七、断线/会话死亡

1. `na-stats.sh` 的 `session_deaths`:短时间猛涨 = 网络/PTY 病。
2. `na-trace.sh` 的 conn/session 段:ws 握手四段耗时、死亡 why。
3. 隧道侧(手机 Termux):`kalo status` / `kalo-ssh.log` 记死因
   (CGNAT IP 漂移是已实锤的头号杀手,v3.13 起 15s 探死自动重建)。

## 八、热更没生效

1. `cat $NA_TMP/loader-pick`(或 na-autopsy 拉回):`pick=hot` 才是
   热更核心,`pick=bundled why=...` 的 why 直说原因。
2. 改了 loader 壳/Java/dex = 热更盖不住,必须
   `bash scripts/build-on-phone.sh` 重打 APK 过安装器(边界见
   docs/active/热更新.md)。
